## 前言

### 为什么C程序员要学SICP？

你可能会问："我已经熟悉C了，为什么要学一本用Lisp的教材？"

**原因**：SICP教的不是"语法"，而是**编程的本质思想**：

| 你在C中遇到的困惑 | SICP给出的答案 |
|-------------------|----------------|
| 递归好难理解 | 递归是最自然的思考方式 |
| 全局变量到处都是 | 如何用不可变数据避免副作用 |
| 代码越来越难维护 | 通过抽象分层管理复杂性 |
| 回调函数嵌套地狱 | 高阶函数让组合更优雅 |
| 解释器/编译器很神秘 | 亲手写一个就懂了 |

### 本教程的特点

- **C语言对比**：每个概念先用C代码展示问题，再用Scheme展示解决方案
- **聚焦核心思想**：不纠结语法，重在理解思维模式
- **实用导向**：学完能应用到你的日常编程中
- **深入底层**：理解编程语言如何工作

### 如何阅读

建议按顺序阅读，但可以重点关注：
- **[第0章](./chapter_0.md)**：Scheme基础语法速成（必读！）
- **第1章**：理解递归和高阶函数
- **第3章**：学习状态管理（C程序员最头疼的部分）
- **第4章**：手写解释器（理解语言本质）
- **第5章**：编译器原理（从高级代码到机器码）

**如果你完全不熟悉Scheme，请先阅读[第0章：预备知识](./chapter_0.md)**

## 核心思想速览

### 1. 函数式编程 ≠ 没有副作用

C代码：
```c
int sum = 0;
for(int i = 1; i <= 10; i++) {
    sum += i;  // 副作用：修改sum
}
```

函数式：
```scheme
;; 不修改任何状态
(define (sum-range n)
  (if (= n 0)
      0
      (+ n (sum-range (- n 1)))))
```

**好处**：更容易推理、更容易测试、更容易并行

### 2. 递归是工具，不是魔法

C代码（你写过的）：
```c
int factorial(int n) {
    if(n == 0) return 1;
    return n * factorial(n - 1);  // 等等，这会栈溢出！
}
```

Scheme（尾递归优化）：
```scheme
(define (factorial n)
  (define (iter product counter)
    (if (> counter n)
        product
        (iter (* product counter)  ; ← 编译器会优化成循环
              (+ counter 1))))
  (iter 1 1))
```

**本质**：递归描述"是什么"，迭代描述"怎么做"

### 3. 数据抽象 > 实现细节

C代码（暴露内部）：
```c
typedef struct {
    int numerator;
    int denominator;
} Rational;

Rational r = {1, 2};
int value = r.numerator / r.denominator;  // 必须知道结构
```

Scheme（隐藏实现）：
```scheme
;; 用户不需要知道内部怎么存储
(make-rat 1 2)        ; 创建
(add-rat r1 r2)       ; 加法
;; 内部实现可以随意改，用户代码不变
```

### 4. 函数是值

C的函数指针：
```c
int (*op)(int, int);  // 声明好复杂
op = add;
result = op(3, 4);    // 调用不直观
```

Scheme：
```scheme
(define op +)         ; 函数就是普通值
(op 3 4)             ; 调用很自然
```

### 5. 解释器很简单

```
表达式 → 求值 → 结果
   ↓
  数字？返回它
  变量？查环境
  (func arg)？求值func，求值arg，应用
```

150行代码就能实现一个完整的Lisp解释器！
